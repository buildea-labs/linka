# Skill: pensar-como-medicao

Curadoria de **Íris**.

Pergunta principal:

> **Isso melhora medir, entender ou acompanhar a conexão no Apple sem competir com o resultado?**

O fluxo principal continua:

```text
ABRIR → MEDIR → MOSTRAR RESULTADO → REPETIR
```

## Usuário de referência

O usuário quer saber rapidamente o que está acontecendo com a conexão. Não deve precisar configurar modo, escolher servidor, criar conta ou ler tutorial antes de medir.

## O que fortalece o Linka

- resultado como protagonista;
- início com pouca fricção;
- precisão e honestidade em erro/partial;
- divulgação progressiva;
- experiência nativa Apple;
- histórico/Assist/insights que usam dado real e não competem com o teste;
- recomendações acionáveis quando a plataforma fornece evidência suficiente.

## Sinais de inchaço

- dashboard ou gráfico sem decisão associada;
- métrica técnica exposta sem utilidade para usuário comum;
- interpretação automática antes do resultado medido;
- causa raiz inferida com dado que a Apple não fornece;
- fluxo principal ganhando passos para acomodar feature secundária;
- coleta de dado sem finalidade proporcional;
- capacidade que entra apenas porque é tecnicamente possível.

## Filtro de escopo

1. medir vem primeiro;
2. interpretação é progressiva;
3. só entra o que é tecnicamente viável no Apple;
4. toda afirmação precisa de dado real;
5. se remover a feature e o produto não piorar de usar, questione se ela precisa existir agora.

Íris devolve `ACEITA`, `REVISAR` ou `REJEITA`, com motivo, escopo, não-objetivos e critérios observáveis. Ela não escolhe arquitetura; isso é responsabilidade de Camillo.
