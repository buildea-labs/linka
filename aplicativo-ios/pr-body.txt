## Implementação anterior
A implementação antiga (`LocalGatewayDiscovery`) assumia que o gateway sempre seria o primeiro IP da sub-rede (`networkHost + 1`), usando o final `.1`. Isso é uma heurística falha. Além disso, o `GatewayProber` baixava o HTML da página do roteador, usava regex para extrair a tag `<title>` e fazia fingerprinting (via `GatewayVendorFingerprinter`) usando cabeçalhos HTTP e conteúdo da página para adivinhar a marca e modelo do roteador.

## Heurísticas removidas
- Cálculo de `networkHost + 1` para adivinhar o final `.1`.
- Scraping de HTML (remoção de regex para extração de `<title>`).
- Fingerprinting de fabricante e modelo.
- Dicionário de cabeçalhos e títulos comuns em `GatewayVendorFingerprinter` (arquivo excluído).

## Mecanismo utilizado para descobrir o gateway
A descoberta foi substituída pelo uso direto de `sysctl` com `NET_RT_DUMP` (tabela de roteamento). O código percorre os endereços da rota ativa de destino `0.0.0.0` e recupera o IP do gateway (`RTAX_GATEWAY`) garantindo que pertence à interface de rede correta via `rtm_index`.

## Tratamento de VPN e redes móveis
Foram adicionadas verificações de interface (`name.hasPrefix("en")`) para ignorar interfaces virtuais de VPN (`utun`) e rede móvel (`pdp_ip`), garantindo que o CTA só apareça para a rede local via Wi-Fi/Ethernet.

## Validações de segurança
O destino do gateway agora é estritamente validado com a função `isPrivateIPv4`, que aceita apenas IPs das faixas privadas locais da RFC 1918 (10.x.x.x, 172.16.x.x - 172.31.x.x, 192.168.x.x) ou link-local (169.254.x.x). Endereços públicos ou loopback retornam `nil`.

## Comportamento HTTP/HTTPS
Em vez de baixar e examinar conteúdo, o `GatewayProber` agora utiliza o método HTTP `HEAD` com um timeout rápido de 0.5s para checar se as portas 80 (`http`) e 443 (`https`) estão abertas. O probe roda de forma assíncrona, tolerando equipamentos que usem qualquer protocolo e mitigando demoras excessivas.

## Testes executados
A suíte `GatewayDiscoveryTests` foi atualizada:
- Adição de testes em `isPrivateIPv4` (comprovando rejeição de loopback e IPs públicos).
- Remoção de testes de fingerprinting.
Todos os 30 testes passaram localmente no macOS/iOS.

## Resultado da Build Release
Build em configuração Release (`xcodebuild build -configuration Release`) executa sem erros e o aplicativo foi compilado com sucesso.

## Validações dependentes de iPhone físico
Testes unitários e o simulador não conseguem expor tabelas de roteamento com Wi-Fi/Celular/VPN simultâneos com 100% de precisão. O que falta validar em *device real*:
1. Conectar a um Wi-Fi onde o roteador não termina em `.1` e validar que o CTA abre o roteador correto.
2. Ligar o 4G/5G (com e sem Wi-Fi conectado) e confirmar se o Linka ignora `pdp_ip` (o botão não deve aparecer para o gateway da operadora).
3. Conectar a uma VPN e garantir que o IP dela não é lido como roteador.
4. Testar o botão com roteadores que exijam HTTPS estrito.
